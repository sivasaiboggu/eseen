# Decisions (Eseen)
Latest user spec (2026-11-11 19:21 IST) supersedes the first: **v1 is open tracking only**. No read-time, no clicks, no AI. Phase 1 click/read code was removed, not hidden.

1. **Combined status by default.** Gmail sends one body to all To/Cc/Bcc, so one pixel cannot say which recipient loaded it. Default: one pixel, one combined status ("All recipients (combined)"), limitation stated in API response and UI. Per-recipient copies are prepared in the backend (mode per_recipient) but NOT enabled in the extension and not authorized for real use. The extension always requests combined.
2. **"Opened" means "no automation signal found", not proof of a human.** Wording follows the spec: Opened / Possibly opened (auto-loaded) / No open detected / Sent. Never "read".
3. **IP rules are inert until ranges are loaded.** rules.json ipRanges are empty; Apple/scanner/data-center IP rules only fire once real published ranges are added at deploy time. UA rules work now. Raw IPs are used in-request only and never stored.
4. **Self-open: only an explicit marker counts as SELF_OPEN.** The extension cannot attach a header to images Gmail's proxy fetches, so the marker rarely applies. The "sender viewed own sent thread" timing guess is NOT used to hide events: that first load is stored as POSSIBLY_OPENED with the reason "could be you, could be the recipient (unverified)". All events are always shown.
5. **Gmail integration: InboxSDK is primary** (@inboxsdk/core 2.2.34, MV3 build, no remote code). Feasibility read from its typings: ComposeView has presending (cancel), send(), getBodyElement(), getTo/Cc/BccRecipients(), addButton(), discard and destroy events. It is implemented in src/content/inboxsdk.ts. Because presending is synchronous, the handler cancels, creates tracking, injects the pixel, then calls send(). **Blockers:** (a) InboxSDK requires a free AppId registered by the project owner (https://inboxsdk.github.io/inboxsdk-docs/); none registered, so the build uses the MutationObserver fallback until VITE_INBOXSDK_APP_ID is set. (b) MV3 InboxSDK needs the extra `scripting` permission plus a background worker to inject its page script; this is beyond the spec's permission list and needs a Web Store justification. (c) Neither path has been run against live Gmail. The fallback selectors are unverified.
6. **Send flow:** the click is held until the pixel exists. If creation fails, the user is asked whether to send without tracking; never silent.
7. **Storage:** MemoryStore now; Postgres schema in backend/migrations (no raw IP, hashed recipient emails with per-user salt, no token column since tokens are HMAC of recipient id).
8. **Dev auth** is a bearer user id. Google ID-token verification is not wired.
9. Nothing deployed; no real emails touched. No legal, GDPR or Chrome Web Store compliance is claimed, only designed toward.
10. **Gmail-proxy opens:** after the first 60s a Google-proxy load is labelled REAL_OPEN internally, but timing cannot prove a person opened it. The reason text says so and the status tooltip says it is not proof.
